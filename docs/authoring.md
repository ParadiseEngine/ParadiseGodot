# Authoring guide

The addon edits prefab documents under `assets/`. Godot scenes provide the editing
surface; `paradise assets build` produces the runtime data.

## Entity nodes and components

Attach `addons/paradise/Authoring/AuthoredEntityNode.cs` to a `Node3D` inside an open
document. Only authored entity nodes are written to that document. A plain GLB
instance can appear in Godot without contributing any runtime data.

Use **Add Component** to add a component and its fields. Clear its **Enabled**
toggle to remove it. Components come from the game's `[Authored]` records in
`.editor/authoring-schema.json`, generated by the launcher build (`paradise host build`).
The addon has no built-in engine component schema.

The schema defines field types, defaults, ranges, units, visibility rules, and
editor visuals. Semantic hints such as meters or seconds work across editor hosts;
runtime code decides which values are valid. A game can implement
`ParadiseGodot.Authoring.IAuthoredEntity` for behavior the schema cannot express.

Three responsibilities stay in the addon:

| Responsibility | Behavior |
| --- | --- |
| Identity | Preserve the document GUID in `paradise_entity_guid`; assign unique GUIDs to new or duplicated entities |
| Placement | Save local position, rotation, scale, and entity parentage |
| Host references | Convert referenced Godot objects to document values |

`meta` and `transform` belong to the document format and are represented by the
node's identity and transform controls, rather than editable component fields.
Avoid naming an authored field `Enabled`: it currently conflicts with the component toggle.

## References and editor visuals

Set a mesh field to a `.mesh` or `.skinnedmesh` document under `assets/`, or its
source GLB. The addon resolves a GLB to the extracted mesh document when saving.
Adding a model as a child does not select it for the component.

For schema fields authored from host objects, select the relevant Godot node:
for example a `CollisionShape3D`, light, camera, or `Sprite3D`. Edit it with Godot's
tools. The addon bakes its values on every save, including changes made outside
the entity inspector. Node paths stay in the working scene; documents receive values.

Schema gizmos can draw a box from component fields, starting at `Y = 0` and extending
downward. Mesh previews and gizmos are derived children and are excluded from saved
entity content.

## Saving

Open prefabs through **Paradise/Open Document…**. Saving their working scene merges
edited fields, component additions/removals, identity, transforms, and baked references
into the original document. Unknown components and untouched payloads are preserved.
An unchanged document is left alone.

If the document changes on disk after opening, the addon refuses to overwrite it.
Your Godot working scene still saves; reopen the document to load the external changes.
Expanded children of prefab instances remain part of their source prefab.

## Working scenes

**Paradise/Convert Project** creates a working `.tscn` per document and a reusable
`.scn` per model under `.editor/godot/`. Current workfiles are reused. When a document
changes, rebuilding carries author-created children across by entity GUID.

These files are derived and gitignored, but can hold editor-only helpers and pending
edits. Deleting them rebuilds the document view and loses any work stored only there.
Commit source documents, assets, and `.meta` sidecars under `assets/`.

## Meshes and textures

`paradise assets watch` or **Paradise/Extract Models** creates mesh, skeleton,
animation, and material documents beside source models. Prefabs reference these
documents; the asset build cooks mesh blobs and KTX2 textures for the runtime.

Godot does not import `assets/`; model previews load GLBs directly. Embedded textures
work with this path. External images under an ignored tree can fail to load in the
preview; passing an absolute base path does not bypass Godot's resource lookup.

## Collision layers

The shape bake reads the nearest `CollisionObject3D` ancestor's layer mask and stores
the index of its lowest set bit. Use single-bit masks: the contract holds one layer,
and the runtime reconstructs membership with `1 << index`. A zero mask maps to index 0.

See the [data contract](contract.md) for authored and built file formats.
